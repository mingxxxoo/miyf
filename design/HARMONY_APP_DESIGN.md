## 1. 产品与目标

**miyf** 是面向家庭 / 宿舍 / 小团队的内部厨房预约与健康数据产品。鸿蒙端是与微信小程序并列的**薄客户端**，不重写业务规则。

| 维度 | 说明 |
|------|------|
| 品牌房间 | 「胡闹厨房」·「胡闹健康」 |
| 明确不做 | 价格、购物车金额、优惠券、支付、电商交易 |
| 预约语义 | 「今天吃什么」，不是外卖下单 |
| 健康边界 | 生活方式参考；禁止诊断、用药、就医结论文案 |
| 角色 | 同一账号可在厨师 / 食客间切换；一客一厨 |
| 登录 | 华为账号为主；开发环境 Mock；手机号验证码仅预留 |

**设计目标**

1. 与小程序信息架构、文案、配色一致，只在导航 / 控件 / 系统能力上体现鸿蒙差异。
2. 一期即可完成「登录 → 选身份 → 加入厨房 → 浏览 → 预约 → 我的」闭环。
3. 华为运动健康、2×2 服务卡片是鸿蒙端差异化能力，不做手表 / 折叠 / 跨设备流转。

## 2. 设计原则

| # | 原则 | 落地 |
|---|------|------|
| 1 | 奶油生活感，非 SaaS | 底 `#FFFDF8`，禁止默认蓝紫、深色模式、玻璃拟态堆叠 |
| 2 | 双主题同骨架 | 厨房灶橙 / 健康薄荷；顶部服务切换只换主题与首页内容 |
| 3 | 口语、无营销腔 | 禁止「爆款」「限时」「立即抢」「购买」 |
| 4 | 鸿蒙控件语言 | 大圆角卡片、底部页签、标题栏文字按钮；不用 Material FAB / iOS 大标题 |
| 5 | 空错可恢复 | 骨架屏 + 一句话空态 + 可重试错误；写库动作需确认 |
| 6 | 薄客户端 | 状态机、库存、AI 降级以服务端为准 |

### 3.2 圆角 / 阴影 / 间距

| 元素 | 规格 |
|------|------|
| 卡片 | 圆角 20vp，描边 `#F1E9DD`，阴影 `0 8px 24px rgba(80,50,10,.08)` |
| 主按钮 | 高 48vp，圆角 16vp，左右边距 16vp，模块渐变，字重 600 |
| 输入框 | 圆角 12vp |
| 胶囊 Tab / 标签 | 全圆 |
| 宫格图标底 | 52vp 圆角方块 |
| 列表边距 | 左右 16vp，卡片间距 12vp |
| 触控热区 | ≥ 40vp |

### 3.3 字体与动效

- 字体：鸿蒙黑体；数字等宽对齐。
- 字号：一级标题 20vp 加粗居左；二级页标题居中；正文 14～15vp；说明 11～12vp。
- 动效：150～250ms，柔和，不弹跳夸张。轻模糊仅用于半模态浮层。

## 4. 信息架构

```text
未登录
 └─ 登录（华为账号 / Mock）
     └─ 无身份 → 选身份（厨师 / 食客）
         ├─ 食客未绑定 → 加入厨房（邀请码）
         │    └─ 已绑定 → Main（底部四栏）
         │         ├─ 首页（推荐 + 预约条 + AI 点菜入口）
         │         ├─ 菜品（分类 + 列表 → 详情）
         │         ├─ 预约（草稿 / 历史 + AI 饮食参考）
         │         └─ 我的（身份 / 厨房 / 进工作台 / 退出）
         └─ 厨师 → 厨房工作台（无底部四栏）
              ├─ 菜品 / 菜谱 / 分类 / 预约处理
              ├─ 食客申请 / 邀请码 / 厨房资料
              └─ AI 建菜（文本提取草稿 → 提交审核）

任意已登录态顶部可切换「厨房 ↔ 健康」
 └─ 健康首页（不进底部四栏）
      ├─ 指标详情
      └─ 数据源（华为运动健康优先）
```

**服务卡片（系统级，不画进 App 页面）**：2×2 卡片展示「备餐中 · 约可取时间 + 菜名」，点击进预约详情。

## 5. 鸿蒙特有交互

| 能力 | 表现 | 不做 |
|------|------|------|
| 华为账号登录 | 登录页主按钮「华为账号登录」；失败可读错误 | 冒充调用 wx-login |
| 华为运动健康 | 数据源第一位；未连接「去授权」；已连接显示范围 / 上次同步 / 立即同步 / 解除 | 端上 Health Kit 另做上报；视觉不用华为红 |
| 2×2 服务卡片 | 奶油底 + 灶橙点缀；一行状态 + 小字菜品 | 信息过载、多预约堆叠 |
| 半模态 | 「说一句话点菜」、筛选；顶小横条；内容区奶油色 | 整页毛玻璃 |
| 对话框 | 圆角 24vp；主按钮在右；破坏项用红 | Material 全屏 Dialog |

导航约定：

- 食客：底部页签 首页 / 菜品 / 预约 / 我的。
- 厨师：从「我的 → 进入厨房」进工作台，自带返回，无四栏。
- 一级页标题居左；二级页标题居中 + 左侧返回箭头。
- 列表主操作放标题栏右侧文字按钮（如「新建」），不用 FAB。

画布规格：**360×780 vp**，底部手势条，状态栏与页面同色、深色图标。只画直板手机竖屏。

## 6. 屏幕清单

编号规则：`L` 登录与入门 · `D` 食客 · `K` 厨师 · `H` 健康 · `A` AI · `S` 系统能力。

### 6.1 入门（一期）

| ID | 屏幕 | 关键内容 | 主操作 |
|----|------|----------|--------|
| L1 | 登录 | 品牌、一句定位文案、华为账号主按钮、开发 Mock 次入口 | 华为账号登录 |
| L2 | 选身份 | 两张大卡「我是厨师」「我是食客」+ 副文案 | 选择后写角色 |
| L3 | 加入厨房 | 6 位邀请码；状态：未绑定 / 待确认 / 已绑定 / 未通过 | 提交申请 |

### 6.2 食客主链路（一期）

| ID | 屏幕 | 关键内容 | 主操作 |
|----|------|----------|--------|
| D1 | 首页 | 厨房名「老王的灶」、今日推荐大卡、库存将尽提示、底部预约条「已选 N 样 · 去预约」、入口「说一句话点菜」 | 进菜品 / 去预约 |
| D2 | 菜品列表 | 分类胶囊（荤菜 / 素菜 / 汤羹 / 主食 / 凉菜）、左图右文或双列卡、库存「今日还剩 8 份」 | 进详情 / 加减草稿 |
| D3 | 菜品详情 | 封面、名称、一句话、口味标签、库存步进器、菜谱步骤、评价 | **加入预约**（非购买） |
| D4 | 预约 | 草稿（餐次 / 人数 / 口味）与历史；状态条：待确认 → 已确认 → 备餐中 → 可取餐 → 已完成；仅 PENDING 可取消；可嵌 AI 饮食参考卡 | 提交预约 / 取消 |
| D5 | 我的 | 头像昵称、当前身份、绑定厨房、切换厨师/食客、退出 | 进工作台 / 退出 |

### 6.3 厨师（二期）

| ID | 屏幕 | 关键内容 | 主操作 |
|----|------|----------|--------|
| K1 | 工作台 | 「下午好，老王」、四格数据、宫格 7 入口带角标、最新待处理预约可确认/驳回 | 确认 / 驳回 / 进子页 |
| K2 | 菜品管理 | 搜索、状态胶囊、库存与上下架；标题栏「新建」；次操作「用文字生成」 | 新建 / AI 建菜 |
| K3 | 处理预约 | 三块汇总 + 流程节点 + 状态推进按钮 | 确认 / 备餐 / 可取 / 完成 |
| K4 | 厨房资料 | 封面、名称、简介、邀请码可复制 | 保存 / 复制邀请码 |
| K5 | 食客申请 | 待确认列表 | 通过 / 拒绝 |

### 6.4 健康（三期）

| ID | 屏幕 | 关键内容 | 主操作 |
|----|------|----------|--------|
| H1 | 健康总览 | 评分环、状态文案、「数据来自华为运动健康 · 今天 08:30」、需关注横幅、指标卡（心率 / 血氧 / 睡眠 / 步数 / 体重） | 进详情 / 切服务 |
| H2 | 指标详情 | 折线、参考区间、平均/最低/最高/记录数；异常琥珀或红标出 | 切换时间范围 |
| H3 | 数据源 | **华为运动健康第一位**（授权范围、同步、解除）；其他源可灰显「即将支持」 | 去授权 / 立即同步 |

### 6.5 AI（四期）

| ID | 屏幕 | 规则 |
|----|------|------|
| A1 | AI 建菜 | 粘贴文本/链接 → 可编辑草稿列表 → **提交审核**，不直接上架 |
| A2 | AI 点菜 | 只匹配当前厨房在售菜；未匹配进「没找到」，禁止编造菜名 |
| A3 | AI 饮食参考卡 | 嵌在预约页；三档合适/需注意/不建议；固定免责声明；失败则整卡不出现 |

### 6.6 系统能力（五期）

| ID | 产物 | 规格 |
|----|------|------|
| S1 | 2×2 服务卡片 | 标题「老王的灶」·「备餐中 · 约 12:30 可取」·「红烧肉 ×1」；点击打开预约详情 |

## 7. 关键状态与文案示例

### 7.1 预约状态机（只展示服务端允许的流转）

```text
PENDING → CONFIRMED → PREPARING → READY → COMPLETED
PENDING → CANCELLED   （仅食客、仅待确认）
```

界面文案：待确认 / 已确认 / 备餐中 / 可取餐 / 已完成 / 已取消。

### 7.2 绑定状态

未绑定 · 待确认 · 已绑定 · 未通过。未通过给出重新申请入口。

### 7.3 空 / 错 / 加载

| 场景 | 表现 |
|------|------|
| 加载 | 奶油底骨架屏 |
| 未加入厨房 | 「还没有厨房」+「去加入」 |
| 无菜品 | 「厨房还在备菜」+「看看别的时候」 |
| 无预约 | 「今天还没定吃什么」+「去选菜」 |
| 健康无数据源 | 「还没连接数据」+「去连接华为运动健康」 |
| 错误 | 展示服务端 `message` + 重试 |
| 写库确认 | 对话框确认；破坏项红色 |

### 7.4 禁用词与按钮对照

| 禁止 | 正确 |
|------|------|
| 购买 / 下单支付 / ¥ | 加入预约 / 提交预约 |
| 立即抢 / 爆款 | （不用） |
| 诊断 / 用药建议 | 一般性饮食参考 + 免责声明 |

免责声明缺省文案：`以上为一般性饮食参考，不构成医疗建议`。

## 8. 与工程分期对齐

| 期次 | 设计覆盖 | 工程目录 / 接口 | 验收要点 |
|------|----------|-----------------|----------|
| 一期 | L1–L3、D1–D5 | `harmony/` 已落地；`huawei-login`、dishes、orders、bindings | 未登录进不了菜品；未绑定不能点菜；无金额 |

| 三期 | H1–H3 | `harmony/pages/health/*`；`/api/health/**`、浏览器 OAuth 轮询 | 华为源优先；失败「暂不可用」 |

| 五期 | S1 | 服务卡片 | `MiyfFormAbility` / `OrderStatusCard`；仅备餐中与取餐提示；点击进详情 |

一期选厨师：已可进入工作台。一～五期鸿蒙主链路已齐。
