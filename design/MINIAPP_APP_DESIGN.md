## 1. 产品与目标

**miyf** 是面向家庭 / 宿舍 / 小团队的内部厨房预约与健康数据产品。微信小程序是主力用户端：登录、浏览、预约、评价、厨师工作台、健康数据与 AI 草稿入口均在此完成。

| 维度 | 说明 |
|------|------|
| 品牌房间 | 「胡闹厨房」·「胡闹健康」——顶部服务切换只换主题与首页内容 |
| 明确不做 | 价格、购物车金额、优惠券、微信支付、电商交易 |
| 预约语义 | 「今天吃什么」，不是外卖下单 |
| 健康边界 | 生活方式参考；禁止诊断、用药、就医结论文案 |
| 角色 | 同一账号可在厨师 / 食客间切换；一客一厨 |
| 登录 | 微信授权：昵称必填、头像可选 → `POST /api/auth/wx-login` |

**相对 v2 的优化目标**

1. **补齐入门闭环**：登录 / 选身份 / 加入厨房此前设计稿缺失，本版纳入主路径。
2. **微信壳适配**：胶囊按钮避让、自定义导航、订阅消息、分享邀请码。
3. **减少视觉噪音**：宫格与列表优先 Lucide 线图标（对齐 `MiniIcon`），首页首屏收敛为「品牌 + 一句问候 + 一块推荐 + 预约条」。
4. **与工程一致**：页面编号对应 `miniapp/src/pages/**`，空错态、状态机文案与后端字段对齐。
5. **与鸿蒙对照**：Token / 文案 / IA 同源，差异只在登录、导航壳、系统能力。

## 2. 设计原则

| # | 原则 | 落地 |
|---|------|------|
| 1 | 奶油生活感，非 SaaS | 底 `#FFFDF8`；禁止默认蓝紫、深色模式、玻璃拟态堆叠 |
| 2 | 双主题同骨架 | 厨房灶橙 / 健康薄荷；`ServiceSwitcher` 只换主题色与首页 |
| 3 | 口语、无营销腔 | 禁止「爆款」「限时」「立即抢」「购买」「下单支付」 |
| 4 | 微信控件语言 | 胶囊避让、原生/自定义导航混用、底部四栏仅食客、半屏 AI 浮层 |
| 5 | 空错可恢复 | 骨架 + 一句话空态 + 可重试；写库需确认 |
| 6 | AI 只出草稿 | 菜品进提审、预约进草稿；失败静默降级，不阻塞主流程 |
| 7 | 薄客户端 | 状态机、库存、权限以服务端为准 |

与鸿蒙 / `miniapp/src/styles/variables.scss` 同源。

### 3.1 色板

| Token | 值 | 用途 |
|-------|-----|------|
| `--cream` | `#FFFDF8` | 页面底 / 导航栏底 |
| `--ink` | `#2B2622` | 主文案 |
| `--muted` | `#8A8178` | 次文案 |
| `--faint` | `#B5AC9F` | 弱文案 / Tab 未选 |
| `--line` | `#F1E9DD` | 分割线 / 卡片描边 |
| `--ko` / `--ko2` | `#F07B1F` / `#FFB36B` | 厨房主色渐变 |
| `--ko-soft` / `--ko-softer` | `#FFF1E2` / `#FFF8EF` | 厨房浅底 |
| `--hg` / `--hg2` | `#18A885` / `#5FCFAE` | 健康主色渐变 |
| `--hg-soft` / `--hg-softer` | `#E7F7F0` / `#F4FBF8` | 健康浅底 |

| `--amber` | `#D99426` | 待处理 / 需关注 |
| `--red` | `#E15A4B` | 异常 / 驳回 / 角标 |
| `--blue` | `#4A90D9` | 进行中 |

状态色只配浅底小面积使用。Tab 选中色：厨房态 `#F07B1F`，健康态切到 `#18A885`。

### 3.2 圆角 / 阴影 / 间距

| 元素 | 规格 |
|------|------|
| 卡片 | 圆角 20rpx≈20px，描边 `#F1E9DD`，阴影 `0 6px 16px rgba(80,50,10,.06)` |
| 主按钮 | 高 48px，圆角 16px，模块渐变，字重 600 |
| 输入框 | 圆角 12px |
| 胶囊 Tab / 标签 | 全圆 |
| 宫格图标底 | 52×52，圆角 17 |
| 列表边距 | 左右 18px，卡片间距 12px |
| 触控热区 | ≥ 44px |

### 3.3 字体与图标

- 字体：PingFang SC / 系统默认；数字等宽感。
- 字号：品牌 Display 28–32；Hero 22；页标题 16–17；正文 13–14；说明 11–12；角标 9–10。
- 图标：业务入口优先 `MiniIcon`（[Lucide](https://lucide.dev) 线图标 SVG）；菜品 / 头像 / 厨房封面在演示稿用 `design/assets/demo/` 真实照片，禁止食物 emoji 墙。
- 动效：150–250ms；半屏浮层轻遮罩，不做夸张弹跳。

### 3.4 页面氛围（相对 v2）

首屏允许极淡的暖色径向渐变（奶油 → 浅橙雾，透明度 ≤ 8%），避免纯平铺死白；**不做**多图层玻璃、紫渐变、霓虹描边。

## 4. 信息架构

```text
未登录
 └─ 登录（微信昵称 + 可选头像）
     └─ 无身份 → 选身份（厨师 / 食客）
         ├─ 食客未绑定 → 加入厨房（邀请码）
         │    状态：未绑定 / 待确认 / 已绑定 / 未通过
         │    └─ 已绑定 → Main（底部四栏）
         │         ├─ 首页（推荐 + 预约条 + AI 点菜）
         │         ├─ 菜品（分类 + 列表 → 详情）
         │         ├─ 预约（草稿 / 历史 + AI 饮食参考）
         │         └─ 我的（身份 / 厨房 / 进工作台 / 退出）
         └─ 厨师 → 厨房工作台（无底部四栏）
              ├─ 菜品 / 菜谱 / 分类 / 预约处理
              ├─ 食客申请 / 邀请码 / 厨房资料
              └─ AI 建菜（文本提取草稿 → 提交审核）

任意已登录态顶部可切换「厨房 ↔ 健康」
 └─ 健康首页（覆盖式，不进四栏）
      ├─ 指标详情
      └─ 数据源
```

## 5. 微信特有交互

| 能力 | 表现 | 不做 |
|------|------|------|
| 微信登录 | 昵称 `type=nickname`、头像 `open-type=chooseAvatar`；主按钮「微信授权登录」用灶橙品牌色 | 冒充微信支付绿作主 CTA；堆砌「手机号一键登录」 |
| 胶囊避让 | 自定义导航时右侧预留 ≥ 100px；标题居中或居左避开胶囊 | 标题被胶囊遮挡 |
| 订阅消息 | 厨师确认新预约前 / 食客预约提交后可请求订阅；失败不挡主流程 | 强制订阅、反复弹窗轰炸 |
| 分享邀请 | 邀请码页支持「复制」+「发给微信好友」 | 公开广场分享厨房 |
| 半屏 AI | `AiPromptSheet`：顶小横条 + 奶油内容区；示例胶囊一句点选 | 整页毛玻璃、自动提交写库 |
| TabBar | 仅食客四栏；厨师走 `navigateTo` 工作台栈 | 厨师页挂四栏 |

导航约定：

- 食客：首页 / 菜品 / 预约 / 我的。
- 厨师：从「我的 → 进入厨房」进工作台，自带返回。
- 全局：`navigationBarBackgroundColor: #FFFDF8`，黑字。
- 列表主操作：搜索条右侧或导航「···」旁文字按钮；不用 FAB。

画布规格：**375×812**（iPhone 逻辑宽），演示壳含状态栏 + 微信胶囊 + 底部 Home Indicator。

## 7. 关键状态与文案

### 7.1 预约状态机

```text
PENDING → CONFIRMED → PREPARING → READY → COMPLETED
PENDING → CANCELLED   （仅食客、仅待确认）
```

文案：待确认 / 已确认 / 备餐中 / 可取餐 / 已完成 / 已取消。

### 7.2 绑定状态

未绑定 · 待确认 · 已绑定 · 未通过。未通过给出重新申请。

### 7.3 空 / 错 / 加载

| 场景 | 表现 |
|------|------|
| 加载 | 奶油底骨架屏 |
| 未加入厨房 | 「还没有厨房」+「去加入」 |
| 无菜品 | 「厨房还在备菜」 |
| 无预约 | 「今天还没定吃什么」+「去选菜」 |
| 健康无数据 | 「还没有同步到数据」+「去连接数据源」 |
| 错误 | 展示服务端 `message` + 重试 |
| 写库确认 | Modal；破坏项红色 |

### 7.4 禁用词

| 禁止 | 正确 |
|------|------|
| 购买 / 下单支付 / ¥ | 加入预约 / 提交预约 |
| 立即抢 / 爆款 | （不用） |
| 诊断 / 用药建议 | 一般性饮食参考 + 免责声明 |

免责声明：`以上为一般性饮食参考，不构成医疗建议`。

## 9. 前后端同步优化（v3.3）

设计稿与工程必须同版本推进：UI 假定的字段 / 汇总接口，后端先提供；前端去掉 N 次扇出与本地猜字段。

### 9.1 本版已落地

| 项 | 后端 | 前端 | 设计对应 |
|----|------|------|----------|
| 厨师工作台汇总 | `GET /api/chef/workbench/summary` | `pages/chef/index` 一次加载 | K1 |
| 菜品准备时长 | `DishVo.prepMinutes` | `dish.ts` 映射 | D2/D3 |
| 推荐菜 | `GET /api/dishes/recommend` | 首页优先推荐 | D1 |
| 加入厨房状态 | 绑定 VO | `pages/join` 状态面板 | L3 |
| 食客订阅 W1 | `GET /api/orders/wx-subscribe-config` + `OrderDinerWxNotifyService`（V37） | 预约页预取 + 提交前授权 | W1 |
| 预约餐次结构化 | `meal_date/type/time` + `guest_count`（V37） | 提交结构化字段；卡片展示 | D4 / K1 |
| 厨房封面 | `POST /api/my-kitchen/cover/upload` | `pages/chef/kitchen` 上传保存 | K4 |
| 健康评分 | `GET /api/health/me/score` | H1 优先 API，失败回落启发式 | H1 |
| 经营统计 | `GET /api/chef/stats` | `pages/chef/stats`；K1 宫格入口 | K1 |

### 9.2 下一迭代（可选）

| 项 | 建议接口 / 改动 | 说明 |
|----|-----------------|------|

## 10. 与工程对齐

| 模块 | 目录 / 接口 | 验收要点 |
|------|-------------|----------|
| 登录 | `wx-login`、昵称头像 | 未登录进不了业务主路径 |

| AI | extract / draft / insight | 草稿需人确认；失败降级 |
